# Eliph

Workflow/state-machine procedure service: a Fastify REST API, an MCP server that exposes it to Claude, and a docs site. npm workspaces monorepo (TypeScript, jest, esbuild).

## Layout
- `packages/core` - graph engine, session manager, store interfaces, in-memory stores
- `packages/sqlite` - SQLite store implementations (better-sqlite3)
- `packages/server` - Fastify API (port 4000, `GET /health`), docs builder
- `packages/mcp` - MCP HTTP server (port 4002 via `MCP_PORT`)
- `docs-site/` - generated by `npm run docs` (gitignored)
- `ecosystem.config.example.js` - pm2 template (real `ecosystem.config.js` is gitignored)

## Commands
- Install: `npm ci`
- Typecheck: `npm run typecheck`
- Test: `npm test` (or `test:core`, `test:server`, `test:mcp`)
- Build: `npm run build` (outputs `dist/server.js`, `dist/mcp-server.js`)
- Dev: `npm start` (API + docs; needs env vars below)

## Env var names
`ADMIN_SECRET`, `JWT_SECRET` (API); `ELIPH_API_URL`, `MCP_PORT`, `PUBLIC_API_URL`, `API_URL` (MCP/server); `ELIPH_API_KEY` (client). See `.env.example`. Tests and CI need none.

## Working from claude.ai (cloud sessions)
- Always work on a branch and open a PR. Never push to `main`.
- Merging to `main` DEPLOYS TO PRODUCTION automatically: a Mac mini polls `main` and deploys commits whose CI is green. CI must pass before merge.
- Use Relay (https://relay.revalent.ai/mcp) for tickets and logging (`create_ticket`, `workbook_add`, `finish_work` with the PR link). Do NOT call `start_work` from a cloud session: it creates a git worktree on the Mac mini, not in the cloud sandbox.
- Production data and secrets live only on the Mac mini. Never commit `.env` files or secret values (this repo is public).
- Dependencies are installed automatically on session start by `scripts/cloud-setup.sh`.

## Autonomous PR loop

No human reviews or merges PRs in this repo. Opening a PR is all an agent needs to do.

- `.github/workflows/agent-review.yml` runs on every non-draft PR from a branch in this repo (never forks).
- Claude reviews the diff, fixes blockers and CI failures itself, and pushes; CI and the review then run again (up to 4 rounds).
- When the review passes and CI is green, the PR is squash-merged and the Mac mini deploys it within minutes.
- Nits never block a merge; they are listed in the review comment.
- A PR that cannot be shipped gets a comment explaining why and the `needs-attention` label.
- Keep a PR as a draft while it is not ready to ship.
